## Live limitations and remaining differences

- Two existing application detail pages returned HTTP 500. Customer, agent, call, OCR, liveness, and usage subpages were not discoverable through those details during this inspection. Their prior source-based migration remains in place; this inspection does not establish live parity for them.
- The visible bank Officers navigation returned HTTP 404. The local officer management implementation is retained.
- Links contained no entries; the application request page exposed its table columns but no reviewable pending request.
- The old quota page reports an application/service billing ledger: bank, plan, application, type, used, remaining, limit, service, and expiry. The current platform quota balance is a different data source. No synthetic used/expiry values or fabricated reconciliation have been added. Import and reconciliation of the real legacy quota ledger remain necessary for that parity.
- No live bank account or record was imported. Local browser fixtures are synthetic. Deployment still requires the real schema, ID mapping, encryption service, email, and external integration contracts described in the existing parity matrix.
